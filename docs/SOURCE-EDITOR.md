# 独立源码编辑器

源码编辑器用于检查和修改字幕或其他文本文件的原始内容。它以独立窗口运行，与主应用的字幕表格互相同步；右侧全文缩略图用于浏览文件结构、拖动定位和核查长文件，不是视频或字幕画面的渲染预览。

## 打开文件

- 在**项目管理**点击“打开文本文件”，通过文件选择器选择已有文本文件。
- 当前项目已打开时，项目卡片的“源码编辑”打开其字幕文件。
- 在**字幕编辑**的字幕文件下拉框右侧点击源码图标，先保存当前编辑内容，再打开当前 ASS 文件。
- 源码窗口内也提供“打开文本文件”。通过文件选择器打开文件会使用独立窗口；项目文件可以直接在当前窗口的资源管理器中切换。

项目仍由项目管理统一创建、打开、切换和关闭。打开源码窗口不会自动打开项目；在资源管理器中选择已打开项目的另一份 ASS 字幕时，主字幕编辑器会同步选择该字幕文件。

## 编辑和导航

编辑器使用 [Microsoft Monaco Editor](https://github.com/microsoft/monaco-editor)，即 VS Code 使用的编辑器组件。编辑器代码、字体及 worker 均随应用打包，从本地加载，不依赖 CDN 或运行时联网。它提供行号、查找替换、撤销重做、自动换行、字体缩放和右侧全文缩略图；ASS 文件可以按段落折叠。源码文本可以正常选择和复制。

ASS/SSA 高亮区分段落、字段、样式、起止时间、注释与覆盖标签；SRT 高亮区分序号、时间范围和文本标签。高亮遵循 ASS 的 Events Format 字段顺序，字幕文本中的逗号不会被当作后续事件字段。

顶部可打开查找替换、切换自动换行、调整字体。底部显示保存状态、行列、文件编码和当前高亮类型。此窗口沿用主应用的界面语言和明暗主题。

## 自动保存开关

顶部的“自动保存”默认开启：停止输入约 **700 毫秒**后提交更改。关闭后，输入只保留在当前编辑缓冲区，直到点击“保存”或按 `Ctrl+S`；尚未保存的项目字幕不会同步到主字幕表格。

自动保存开关和侧栏显示状态会保留到下次启动，多个源码窗口使用同一份偏好。开启自动保存时，当前合法的未保存更改会按自动保存规则提交；无效语法或版本冲突仍需要先处理。

关闭自动保存后，如果切换文件或关闭窗口时存在未保存内容，应用会先显示“保存”“不保存”“取消”。保存成功才继续；选择“不保存”会放弃当前修改与对应恢复草稿；取消则留在当前文件。自动保存开启时会先尝试保存，失败时也会保留当前内容并提示处理。

## 项目资源管理器

左侧资源管理器以文件树显示当前项目的文件和子目录，目录按需展开，避免为大项目一次加载所有内容。点击资源管理器图标可隐藏或重新显示侧栏；编辑区获得焦点时也可使用 `Ctrl+B`。侧栏隐藏后编辑区会使用释放的空间，刷新按钮可重新读取项目文件。

字幕文件带有专用图标，当前文件会高亮。点击可查看的文本文件会在**同一个源码窗口**切换；来回切换时保留各文件的编辑视图与撤销历史。媒体和其他二进制资源仅展示，不能作为文本打开。

已打开项目中的已登记 ASS 字幕可通过文件树直接切换，主应用会同步选择同一字幕文件，之后保存继续进入该文件的工程保存流程。这只切换项目内部字幕，不会打开其他项目。项目未打开、已关闭或在回收站中时，仍需先返回项目管理处理项目状态。

## 项目字幕的双向同步

当前项目中正在选择的 ASS 文件会显示“项目字幕 · 双向同步”。合法的源码保存会通过主应用的字幕编辑流程应用到工程，保留项目身份和可匹配条目的 ID，并纳入撤销历史；保存文件保留提交的原始 ASS 文本。随后可继续使用表格、样式设置、视频预览和导出功能。

主应用的编辑会在源码窗口没有未保存内容时自动反映到窗口。同步检查约每 **1.2 秒**进行一次，处理中的保存或主编辑操作可能使更新稍后显示；这不是逐按键同步。

两边同时改动时采用版本和内容校验：如果保存基线已经变化，应用暂停该窗口的自动保存，保留窗口中的编辑内容，不直接覆盖另一边的修改。冲突提示提供：

- **重新载入**：采用主应用或磁盘上的最新版本，放弃当前源码缓冲区与对应恢复草稿。
- **另存副本**：将当前缓冲区保存为新的 UTF-8 文件，再决定如何合并。副本不会自动成为项目字幕，不允许覆盖已有文件。

只有**项目管理中已打开项目、且当前选择的 ASS 字幕文件**允许保存项目源码。资源管理器可以在当前项目内切换已登记的字幕文件；关闭项目或项目文件出现恢复冲突后，相应源码窗口转为只读。要继续编辑，请先在项目管理打开对应项目。源码窗口不能借此绕过项目管理。

## 不完整编辑和恢复草稿

编辑中的 ASS 可能暂时缺少字段或有非法时间。项目字幕保存前会解析验证；验证失败时不将无效内容写入正式项目文件，也不替换表格中的字幕。窗口保留当前内容并显示保存错误，修正后重新尝试保存。

每次保存尝试先将原始缓冲区写入应用配置目录的 `source-editor-drafts`，因此未通过验证或同步校验的源码仍有恢复草稿。重新打开文件时会尝试恢复该草稿；草稿版本与当前文件不同则先提示冲突。成功保存、撤销回已保存内容、冲突时重新载入，或明确选择“不保存”后，会清理对应草稿。自动保存有等待时间，关闭自动保存后的新输入若尚未手动提交，也不保证已写入恢复草稿。

这些草稿是小型文本恢复记录，保存于应用配置目录，而媒体、ASR 模型及运行环境继续保存在各自的项目或资源目录。配置目录可从**设置 → 打开配置目录**查看。

## 文件与编码范围

支持已有的 `.ass`、`.ssa`、`.srt`、`.vtt`、`.txt`、`.md`、`.json`、`.jsonc`、`.yaml`、`.yml`、`.toml`、`.ini`、`.cfg`、`.log`、`.csv`、`.xml`、`.html`、`.css`、`.js`、`.ts` 和 `.py` 文件。ASS/SSA、SRT 提供专门高亮；其他文件提供文本编辑，部分格式沿用 Monaco 的基础高亮，不提供完整 VS Code 语言服务。

文件上限为 **10 MiB**。支持严格 UTF-8、UTF-8 BOM 和带 BOM 的 UTF-16 LE；普通文本保存保留原编码，写入后仍须符合大小上限。其他旧编码、二进制文件、网络文件及符号链接等不属于首轮支持范围。普通文本通过临时文件和原子替换保存，保存前后校验原文件版本；文件被外部修改时拒绝覆盖。

只有项目内当前 ASS 会在保存前接受字幕语法校验并同步主编辑器。独立打开的普通 SRT、ASS 或其他文本按原始文本保存，不会自动导入项目，也不进行完整语法验证。需要将独立字幕加入项目时，仍使用项目文件页的导入功能。

文件被删除、移动或无法读取时，窗口保留已显示内容并切换为只读，避免向失效路径继续保存。可先另存副本，再在项目管理处理项目或文件状态。

## 关闭窗口

关闭源码窗口时依据自动保存开关处理未完成的修改；主应用退出也会等待源码窗口处理保存。自动保存关闭或保存失败时，使用应用内提示提供“保存”“不保存”“取消”和“另存副本”。“不保存”会删除当前文件对应的恢复草稿，应在确认不需要当前内容后使用；“取消”会终止本次关闭或应用退出，继续保留当前编辑。

编辑器不是完整 VS Code 工作台：首轮不提供扩展市场、终端、调试器、Git 面板或 VS Code 插件兼容。资源下载和环境配置统一位于[资源管理使用说明](USAGE.md#配置处理引擎)，项目生命周期见[媒体项目](PROJECTS.md)，ASR 模型配置见[ASR 工作台](ASR.md)。
