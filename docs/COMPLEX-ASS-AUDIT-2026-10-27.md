# 复杂动画 ASS 导入、编辑与往返验证

## 应用入口

已有工程在“项目管理 → 项目文件 → 字幕文件”中导入 ASS、SSA、SRT，也可点击“查找内嵌字幕”从项目媒体选择文本字幕轨。每次导入新增一个独立 ASS，同名自动编号，保留原有字幕及导入原件。SRT 转换后作为 ASS 编辑，不会沿用 SRT 的编辑限制。字幕编辑页的文件夹入口可返回项目管理处理导入。

MKV 字体在创建项目时提取并校验到项目目录，已有项目烧录外部字幕时也会按需补齐；不安装到 Windows。项目视频导出和转到视频处理默认使用 MKV 附件复制，保留字体；转为 MP4 等不支持附件的容器时移除该选项。MP4 文本字幕无法保留完整 ASS 特效，核查此类作品应使用 ASS/MKV 或烧录。

## 素材与保真检查

本地测试素材为 `tests/media/[KitaujiSub] Make Heroine ga Oosugiru! [06][WebRip][HEVC_AAC][CHS_JP&CHT_JP].mkv`。素材不入库，测试仅写入 `.test-data`。本次验证没有修改素材或安装字体。

文件为 479,837,312 字节、1440.078 秒、1920×1080 HEVC/AAC。全局字幕流 2 为 `chs_jp`，流 3 为 `cht_jp`，均为 ASS；流 4–24 为 21 个 OTF/TTF 字体附件。字幕使用附件中的字体子集名称，例如 `WN3WUANX`、`ZAD4M67W`、`81L88QIN`、`J7FWJW9T`。

| 项目 | CHS/JP，流 2 | CHT/JP，流 3 |
| --- | ---: | ---: |
| 提取 ASS 字节数 | 4,505,903 | 4,379,664 |
| 事件总数 | 10,112 | 10,506 |
| 其中注释 | 21 | 21 |
| 原始样式数 | 13 | 13 |
| 包含绘图标签的事件 | 5,493 | 5,887 |
| 包含变换标签的事件 | 785 | 830 |
| 包含裁剪标签的事件 | 4,162 | 4,216 |
| 包含移动标签的事件 | 663 | 695 |
| 包含卡拉 OK 标签的事件 | 4 | 4 |
| 包含局部字体标签的事件 | 110 | 110 |
| 最长单条文本字符数 | 2,295 | 1,929 |
| 解析 / schema 校验 / 序列化，毫秒 | 111 / 49 / 42 | 93 / 42 / 35 |

以上耗时为一次本机运行，仅用于检查约一万条特效字幕的处理规模。图层为 0、7、8；所有事件的 Effect 列为空，实际特效在 Text 列的 ASS 覆盖标签和矢量命令中。OP 从 126.03 到 207.24 秒，ED 从 1350.59 到 1420.87 秒。

`tests/integration/complex-ass.test.ts` 独立比较原始 ASS 中的每一条事件与解析后的事件，再比较保存并重开后的事件，包含时间、顺序、层、样式、角色、边距、效果、注释状态和完整正文。原始 13 个样式逐行一致；标准化额外添加未使用的 Default 样式。脚本信息、字体子集注释和其他章节也保持一致，ASS 导出没有报告精度或格式损失。

该测试提取所有字体附件，在 126.4、155、1355 秒用真实 FFmpeg/libass 将两条字幕分别绘制到相同的 1080p 背景。原始 ASS 与往返 ASS 的全部 6 组像素摘要一致，且均包含可见字幕。此项验证覆盖 OP 卡拉 OK、OP 动画绘图和 ED；它不代替整个 24 分钟逐帧审片。

字体提取使用 `ensureProjectFonts`，21 个附件全部通过字体签名及 SFNT 表范围校验。资源仅保存于工程的 `fonts/attached-<UUID>` 中，以来源路径、大小、修改时间及每个文件的 SHA-256 验证缓存；不安装系统字体。文件名由流编号和实际字体类型生成，不采用附件路径。资源限制为 64 个字体、每个 32 MiB、总计 128 MiB；符号链接、超限数据和伪装成字体的可执行内容不会进入字体资源目录。新一代资源和缓存指针通过原子重命名发布，失效的旧资源保留，失败仅清理当前操作的暂存文件。

`tests/integration/project-fonts.test.ts` 另外使用自行生成的 980 字节 TrueType 字体构造小型 MKV，验证提取和复用缓存、带字体的 ASS 烧录与默认替代字体确有像素差异，以及 MKV 导出后字体附件可按原字节重新提取。该测试无需下载或依赖动画素材。

当前限制为单个字幕文件 10 MiB、100,000 条事件、单条正文 10,000 字符、1,000 个样式、100 个附加章节、每组格式最多 64 个字段。此素材均在范围内；无须为其放宽限制。ASS 时间保存精度为 10 毫秒，此素材原始时间已符合该精度。普通 CI 另有不依赖媒体文件的复杂标签单元测试。

复现命令：

```powershell
npx vitest run --config vitest.integration.config.ts tests/integration/complex-ass.test.ts --disableConsoleIntercept --reporter=verbose
npx vitest run tests/unit/subtitle-ass.test.ts
```

真实媒体集成测试需要 PATH 中的 FFmpeg/ffprobe；本地素材不存在时自动跳过，不下载素材。Windows 受限沙箱中的 Vitest 临时缓存可能触发 `EPERM rename`；此次在获准的仓库测试进程中完成验证。首次往返集成测试耗时约 5.6 秒。

## 完整工程界面实测

`scripts/complex-project-smoke.mjs` 使用真实 Electron/libmpv GPU 合成及独立 `.test-data` 配置，将整部视频复制到隔离项目，完整执行波形和帧索引预处理。首次完整运行预处理约 310.8 秒，随后 CHS/JP、CHT/JP 导入约 2.2 / 4.2 秒。分别修改一条普通非绘图文本事件，保存并关闭重开，逐条核对全部事件及原有 13 个样式，其余内容保持一致。两条语言在 126.4、155、1355 秒各取得一张 GPU 预览图，OP 的彩色卡拉 OK、复杂字幕绘图及 ED 字形正常显示。外部 SRT 导入为第四个 ASS，原视频 SHA-256 与修改时间未变，未出现应用错误。

该检查使用开发构建，而非替换已有安装。完整单元测试 296 项通过；集成测试 96 项通过、8 项按配置跳过。新增的原生 libmpv 检查还验证了空白工程不会误显示原内嵌字幕，以及重载预览后保持用户选择的字幕关闭/内嵌轨道状态。当前仍使用 libass 渲染，不宣称与全部 VSFilter 扩展或不同渲染器逐像素一致。

完整界面复现（需要本地素材与真实 GPU，约数分钟）：

```powershell
npm run build
$env:MUXIVRA_COMPLEX_PROJECT_SMOKE='1'
node scripts/complex-project-smoke.mjs
```
