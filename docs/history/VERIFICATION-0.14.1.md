## 分片时间精度复验

读取用户实际报告的 187.371 秒 MP4，在隔离配置中重新执行完整 Whisper large-v3 GPU 识别，默认分为 120 秒和 67.371 秒两片。测试不修改源视频、现有任务结果或源文件旁的 ASS 工程。

| 分片 | 原始段数 | 原始段时间含小数 | 使用 token 细化后含小数 |
| --- | --- | --- | --- |
| 第一片 0–120 秒 | 31 | 0 | 31 |
| 第二片 120–187.371 秒 | 20 | 20 | 20 |

首片原始段时间全为整秒，但完整 JSON 中有有效的小数 token 时间。适配器读取语音 token，排除时间戳与控制 token，将边界映射回媒体时间轴。测试确认两片均保留小数，统一结果没有越过媒体时长，SRT 毫秒往返一致，ASS 以格式规定的 10 毫秒单位往返一致。

新增单元回归覆盖两片偏移、token 筛选、缺失或非法首尾时间、零长度对齐以及 ASS/SRT 导出。真实视频报告为 `artifacts/qa/asr-timing-report.json`；分辨率保留不代表对齐必然正确，仍可按实际用途手动校正。

旧任务的普通 JSON 没有 token 数据，不能恢复其缺失的时间。升级后重新识别可生成细化后的初稿，不自动改写现有工程。

## Whisper large-v3 安装与推理验证

参考运行包为 whisper.cpp b5454 的 Windows x64 CPU 和 CUDA 12.4 版本；模型为完整 `ggml-large-v3.bin`，大小 3,095,033,483 字节，SHA-256 为 `64d182b440b98d5203c4f9bd541544d84c605196c4f7b845dfa11fb23594d1e2`，没有改用 turbo 或量化模型。

- 从官方资源取得运行包和权重并校验摘要；集成复验将已取得的原始字节流送入应用的安装器，完整执行流式大小/摘要校验、解压、运行程序检查和模型自动登记，不重复下载大文件。
- 在本机 NVIDIA GeForce RTX 3060 Laptop GPU（6 GiB）上，通过标准任务工作流识别示例 MP3 的 30–42 秒区间，语言 `zh`、显式 GPU、Beam size 5。
- 任务完成并返回 3 条带时间字幕；统一结果时间均落在媒体的 30–42 秒区间。日志确认模型类型为 large v3，加载 CUDA 后端并实际使用 CUDA0。
- 初次尝试的 CUDA 11.8 运行包缺少所需 cuBLAS 动态库，会退回 CPU；应用显式 GPU 验证将其判为失败。下载清单已改用包含依赖的 CUDA 12.4 运行包。

安装与短区间推理报告为 `artifacts/qa/asr-large-v3-report.json`；长视频分片另按上一节复验，测试结果不承诺所有媒体的识别质量或长时间运行性能。

## 复验与范围

执行命令与真实模型测试开关见 [开发文档](../DEVELOPMENT.md)，使用流程与后端协议见 [ASR 工作台](../ASR.md)。本轮执行 `npm test`、启用 `MUXIVRA_ASR_REAL=1` 的 `npm run test:integration`、启用 `MUXIVRA_ASR_TIMING_SOURCE` 的长视频专项、Windows 打包（包含构建）与 `scripts/package-check.mjs`；打包后设置 `MUXIVRA_EXECUTABLE` 执行 ASR 界面检查。

模型及运行包需用户在工作台下载或导入。whisper.cpp 每块启动并加载模型一次，暂停在块结束时生效；取消可终止当前进程。自定义模型需要自己的推理依赖，不能把不同格式的权重交给同一加载器。附带的 faster-whisper Python 适配器已检查语法与接口，未安装其依赖或执行该后端的模型推理。

ASR 暂仅通过 GUI 使用，没有新增 MCP ASR 工具。代码签名、许可与发行要求见 [发行文档](../DISTRIBUTION.md)。
