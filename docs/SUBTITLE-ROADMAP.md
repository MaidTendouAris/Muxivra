# 字幕编辑功能评估与改造范围

评估日期：2026-10-12。差距评估保留改造前 0.9.0 字幕代码作为基线；参考对象为用户指定的 [TypesettingTools/Aegisub](https://github.com/TypesettingTools/Aegisub) 及其官方文档。下文的历史基线不代表重构后的功能，当前交付范围另列于本节。

## 首轮重构边界

用户已确定：编辑工程统一采用 ASS，输入与导出范围为 SRT、ASS、SSA；SRT 作为 ASS 的降级导出格式，选择 SRT 时限制 ASS 专属编辑项。没有必须兼容的旧编码或其他字幕格式。

导入视频或音频后立即在源媒体目录创建同名 `.ass` 工程。已有同名 ASS 时载入继续编辑；工程或目录不可写时由用户选择工程位置，已有内容复制到新位置，取消选择不替换当前工程。自动保存间隔为 60 秒，手动保存与独立恢复缓存同时提供保护；保存前检测工程外部变化，避免覆盖其他程序的修改。

首轮实施文档基础、工程安全、高效条目编辑与基础 ASS 样式。精细音频时间轴、频谱、关键帧/VFR 索引和视频上可视化排版仍按后续阶段交付，不用全片波形概览代替专业打轴。

不要求直接兼容 Aegisub 的 Lua/MoonScript 插件。卡拉 OK、矢量绘图/复杂特效、字体附件与人工翻译辅助不列为首轮必须交付，后续可独立补齐。

### 本轮交付状态

| 范围 | 本轮实现 | 仍待后续交付 |
| --- | --- | --- |
| 工程与格式 | ASS 为内部文档；SRT/ASS/SSA 读写；保留样式、事件元数据、注释及未知字段/章节；SRT 单独降级并确认 | 额外字幕格式与旧编码兼容没有列为首轮目标 |
| 工程安全 | 媒体同目录同名 ASS；已有工程载入；不可写时另选位置；手动保存、60 秒自动保存、恢复缓存、最近 20 份备份及外部修改保护 | 多工程并行、跨设备同步与备份管理界面 |
| 条目编辑 | 50 条分页与页码跳转；多选、复制粘贴、删除、拆分合并、搜索替换、时间偏移、批量撤销及逐项质检 | 工作区面板拖动、复杂条件选取与阅读速度/行长质检 |

| 专业打轴 | 保留 mpv 定位、逐帧与全片波形概览 | 波形缩放/平移、拖动起止、选区试听、频谱、PCM 缓存、关键帧与 VFR 索引 |

分页限制实际渲染的条目数量，本轮没有声称已实现虚拟全表或专业音频时间轴。工程文件中的 ASS/SSA 时间量化到 10 毫秒，恢复缓存保留原整数毫秒精度；这与编辑、导入时保留时间值是不同层面的保证。验证内容见 [验证记录](VERIFICATION.md)。

重构前的 Muxivra 具备基础 SRT 校改能力，能够导入字幕、修改文本和时间、结合 mpv 预览并导出。本轮完成 ASS 文档和工程安全基础后，仍需继续建设音频打轴、可视化排版及自动化，才能接近 Aegisub。以下四阶段规划保留评估时的完整范围；当前实现以本轮交付表为准。

Aegisub 的翻译助手是人工翻译工作区，Automation 是脚本框架。语音识别、自动翻译、说话人识别和 AI 自动打轴不应计入“接近 Aegisub”所必需的核心功能；如需要，应作为额外模块另行确定模型、下载量、硬件需求及服务来源。不能用功能数量给出可信的完成百分比：文档保真、精细打轴和脚本兼容的成本远高于新增一个按钮。

## 建议交付范围

### 第一阶段：文档基础与高效编辑

建立带版本号的 ASS 字幕工程模型，保留内部整数毫秒精度与旧会话迁移；增加 SRT 升级导入、ASS/SSA 解析、结构保留与 ASS 工程保存。增加显式保存/另存为、恢复备份、媒体关联、多选、复制粘贴、插入、拆分合并、搜索替换、选中范围偏移及基础质检。SRT 输出模式限制样式与事件元数据编辑；导出单独降级，不修改原 ASS 工程。

界面采用可调宽度的媒体区与编辑区，下方为虚拟化字幕表格；文本、时间为常用编辑项，元数据与脚本属性放入可展开区域或二级页面。支持大字号和可调整行高。现有普通界面文字不允许选择的规则继续保留，字幕文本输入框保持正常选择和复制，条目复制通过明确的编辑操作完成。

验收：SRT 升级前后内容/毫秒往返不变；含逗号、换行、ASS 标签、注释及未知字段的文件往返后保留未修改数据；批量编辑可一次撤销；万条字幕滚动与输入不被全表刷新阻塞。ASS 转为 SRT 必须列出将丢失的样式/层/特效并让用户确认，不能静默替换工程源文件。

### 第二阶段：专业打轴

用分块 PCM/多级峰值缓存替代固定 2,000 点概览。提供时间标尺、缩放、平移、拖动起止、吸附、当前/相邻条目标记、选区播放、首尾片段试听、提交后下一条、音轨/声道选择；频谱在同一音频工作区切换。增加真实帧时间与关键帧索引、VFR 时间码导入导出、帧单位操作、可配置前后余量/间隙/吸附后处理。

验收：长音频不一次载入全部 PCM 到渲染进程；缓存生成和索引有进度、可取消、可复用；更换媒体及时停止旧请求；CFR/VFR 测试视频按实际帧时间操作，不能仅用平均帧率换算。后处理先预览变化范围，再一次提交并支持撤销；叠加字幕不被默认删除。

### 第三阶段：ASS 样式与排版

增加样式编辑器/样式库、颜色与透明度、字体检查、脚本分辨率、层/角色/效果、覆盖标签高亮与常用标签 GUI。预览直接使用工程的 ASS 内容。增加视频坐标定位、移动、旋转、缩放、矩形裁剪，随后补矢量裁剪与绘图；提供分辨率重采样与预览/烧录一致性检查。

工程继续使用 mpv 播放，编辑工作区保留时间轴和表格。样式、标签、字体与脚本属性采用嵌套卡片和二级页面，避免将全部专业参数堆在主界面。高级标签允许原文编辑；GUI 只改其负责的字段，保留未理解的标签。

验收：样式导入导出不丢引用，丢失字体可见提示；位置/裁剪坐标正确处理视频缩放、黑边、脚本分辨率与高 DPI；测试涵盖多层重叠、移动、旋转、RTL 文本、中文/日文、字体回退。预览和 FFmpeg 烧录用同一份 ASS、同一字体集合，并记录渲染版本差异，不能承诺不同引擎版本逐像素一致。

### 第四阶段：高级创作与兼容

补充卡拉 OK 音节打轴、模板、人工翻译助手、词典拼写检查、字体收集、附件及导出过滤链。如果需要直接运行现有 Aegisub 脚本，还需单独实现 Automation 4 API、Lua/MoonScript 运行时、字幕对象、宏注册、撤销、进度/取消、对话框和相关库，并建立指定脚本的兼容性测试。

“能执行 Lua”不等于“兼容 Aegisub 脚本”。应先确定实际要使用的脚本和所需 API；运行第三方脚本使用独立进程，限定文件访问、提供超时和取消，脚本修改在成功后一次提交。MCP 可另行提供结构化字幕编辑申请，但不替代音频打轴或 Automation 4。

## 需要改动的核心模块

| 模块 | 改动范围 | 规模判断 |
| --- | --- | --- |
| 文档与格式 | `Cue/SubtitleDocument`、共享校验、SRT/ASS/SSA 适配器、无损结构保留、时间精度、旧会话迁移 | 大：现有单数组不足以保存样式、头信息、附件和扩展数据 |
| 编辑状态 | 从组件内整数组复制改为文档命令与合并历史；多选、可取消批量操作、工程恢复 | 大：关系到所有编辑动作和保存可靠性 |
| 工作区 | 表格虚拟化、可调整面板、播放/打轴焦点、上下文快捷键、二级工具页 | 大：现有页面需拆为独立文档/时间轴/样式组件 |
| 音频与视频索引 | 后台任务、分块缓存、频谱、PCM 选区播放、帧时间/关键帧、轨道选择 | 大：需要新的缓存和查询接口，不能复用当前波形数组解决 |
| ASS 预览 | 临时字幕格式、更新策略、字体一致性、画面编辑坐标层 | 大：特别需要验证原生 mpv 与可视化工具叠层 |
| 导出与转码 | 明确工程保存/格式转换/烧录，损失提示、字体、脚本分辨率、参数联动 | 中至大：现有安全路径与任务队列可复用 |
| 自动化兼容 | Lua/MoonScript、Automation 4 接口、依赖库、独立执行器与兼容用例 | 独立大模块：在确认脚本清单后再定范围 |

建议工程数据分为文档内容（格式、脚本信息、样式、事件、附件、保留的未知段）与工作区状态（媒体、音轨、选中条目、时间轴视区、面板布局）。事件保留稳定 ID；时间内部继续为整数毫秒，ASS 导出按其时间格式处理量化并明确提示，不反复往返损失精度。导出适配器负责格式降级，不能以 FFmpeg 转为 SRT 代替 ASS 解析。

现有 mpv 是 Windows 原生子窗口，当前通过挖去遮挡区域使 HTML 菜单可见。可视化排版需要透明坐标、路径及拖动手柄，不能直接把当前菜单遮挡方案当作完整绘图层。第三阶段前应制作小型验证：原生透明叠层或 mpv 渲染接口嵌入，验证画面、鼠标、DPI、全屏和截图，再决定实现方式；播放器引擎仍使用 mpv。

频谱计算、帧索引、字体扫描及批量导出应放在后台，并提供加载、进度、取消和错误状态。缓存按媒体标识、文件变更信息、轨道和分析配置区分，并设置大小上限。长期工程与一次转码记录分别保存。
