# 资源管理

资源管理使用标题右侧的 **主页 / ASR / 环境 / 一键部署 / 网络检测** Dock。视频和音频处理也使用同一位置的 Dock；均无数字角标，不再占用底部工作区。资源页固定在窗口内，内容只在卡片内部滚动。

## 主页与 FFmpeg

主页管理当前引擎、下载、导入、PATH 检测与已添加引擎切换。新下载的 FFmpeg / ffprobe 存放在 `<安装目录>/engines/ffmpeg`，不再使用 C 盘 AppData 作为默认引擎下载目录。手动选择的外部引擎继续直接使用其路径，不会擅自移动系统文件。

右侧概览显示就绪模型、运行环境、模型文件数量，以及 ASR 的实际存储位置和管理入口。

## ASR：文件与可用模型

1. 在“模型文件”卡片下载官方 Whisper、Qwen、MOSS 模型或辅助对齐器，也可导入本地完整模型。导入不要求已配置 Python，复制到安装目录后原文件保留。
2. 下载/导入成功仅表示文件已准备，不代表模型可以识别。点击“配置此模型环境”到环境页完成配置；已有经验证的环境可直接绑定。
3. “已配置模型”显示可用性、环境、路径和识别参数概览。“配置识别参数”打开按模型保存的设置页，包括语言、精度、推理与兼容选项。
4. ASR 工作台只列出可用模型。音轨与起止区间属于每次任务，在工作台设置。项目创建、打开与关闭仍由项目管理负责。

移除模型/环境记录保留实际文件；被任务或模型引用的记录受保护。自定义 JSON 后端继续作为兼容入口，不会自动修改它所指定的外部环境。

## 环境：先准备文件，再配置

环境页左侧直接显示已注册的 Python 环境及 Whisper 原生运行包。Python、PyTorch、CUDA 运行库、Transformers 版本、解释器路径和引用模型无需展开即可查看；完整依赖、检查时间和诊断可展开。

右侧选择目标模型与 NVIDIA GPU，分开准备资源：

- **Python 基础运行时**：应用专用 CPython 和 uv 工具。
- **PyTorch / CUDA 与模型依赖**：按后端、Python 和 CUDA 配置生成并校验完整离线 wheel 包。Qwen 与 MOSS 的 Transformers 主版本不同，使用各自环境。
- **Whisper CUDA 运行包**：原生程序和配套 DLL，无需 Python。

按钮分别提供下载和导入。Python / 依赖导入选择包含 `muxivra-resource.json` 的完整应用资源目录；可从另一台设备复制已准备的资源目录。清单记录版本、文件大小和 SHA-256，导入时验证并复制。依赖包必须匹配目标后端和 CUDA 配置。Whisper 导入已解压的运行包目录。

环境页只管理现有环境、基础运行文件的下载和导入，以及外部 Python 的兼容配置。自动安装入口统一放到独立的“一键部署”页。

## 一键部署

选择目标模型、NVIDIA GPU 和可选词级对齐器，点击“检查可复用资源”。预检列出 Python、对应后端与 CUDA 的依赖资源、模型和对齐器的本地位置，以及哪些文件仍需下载。检查会发现受管资源目录中已准备的组件。

开始部署后会再次读取本地资源。已配置的匹配环境实际检查 CUDA；没有匹配环境时，复用已准备的 Python 和依赖包，只下载缺失项，再使用带哈希的离线依赖锁创建隔离环境。Qwen 和 MOSS 保持各自的依赖隔离。下载工具和共享 wheel 缓存继续复用。已有资源校验失败时停止并报告错误。

## 网络检测与镜像

默认使用官方源。网络页分别管理 GitHub 发布、GitHub 源码、Astral Python、PyPI、PyTorch、Hugging Face 和 ModelScope 的入口。添加镜像时填写类型、名称、HTTPS 基础地址，然后在对应类型中选择并保存；选择“官方源”即可恢复该类型的默认入口。镜像需要提供与所选官方入口相同的路径布局。软件保留固定版本、哈希校验和 TLS 验证。

检测访问当前选中的入口，跟踪重定向、系统代理和 DNS，不下载模型权重。“复制完整检测报告”包含应用版本、平台、配置版本、实际地址、响应状态及错误原因。入口成功不代表所有 CDN 均可访问。

AI 通过 MCP `get_download_sources` 读取配置与 revision，使用 `request_download_sources` 提交完整配置和用途。即使客户端已有其他操作权限，源变更也始终停留在待审核状态。用户必须在 MCP 交互页核对当前和申请地址后批准；旧申请不能覆盖已经变化的设置。没有供 AI 自动批准的接口。

## MCP 历史

MCP 交互页记录所有已认证的协议请求，包括初始化、工具发现、资源读取、查询、修改、申请和失败操作。每页 50 条，按需读取持久化分页文件，不自动清理历史。每条记录保留请求、结果、状态和耗时，敏感凭据隐藏，超长文本标记为摘要。应用中断时尚未结束的操作标记为中断，不自动重放。升级前没有记录的历史无法补录。

已有系统 Python / Conda 可通过兼容选项注册和检查，或使用“复制环境配置提示词”。自动检测不会递归扫描整个磁盘，也不会自动修改外部环境。

## 存储与隔离

所有大型受管文件保存在安装目录的 `asr` 中：模型位于 `models`，可搬运的资源位于 `components`，隔离环境位于 `environments`，共享 wheel 位于 `packages`，下载与依赖缓存位于 `cache`，临时文件位于 `temp` 或受管暂存目录。轻量注册记录仍位于当前用户应用配置目录。

Python 基础运行时可以复用。环境的逻辑依赖保持隔离；uv 通过稳定的本地索引与带哈希的依赖锁定复用缓存，对相同内容的依赖文件使用同卷硬链接，无法硬链接时复制。升级某一后端时创建或校验该后端的环境，不把 Qwen 的 Transformers 4 与 MOSS 的 Transformers 5 安装到同一 site-packages。

安装盘不可写或空间不足会报错。软件安装在 C 盘时，这些资源也会位于 C 盘；选择其他磁盘安装可减少 C 盘占用。资源下载仍需要目标设备能够访问对应官方渠道；准备完成后的环境配置可以离线进行。

安装和更新保留已有项目、模型、环境与用户配置。安装器不再提供“全新安装”或自动清理个人数据的选项。
